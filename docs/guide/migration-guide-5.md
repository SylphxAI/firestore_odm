# Migrating from 4.x to 5.0

5.0 is a clean break (ADR-0002): the ODM means exactly what `cloud_firestore`
means. There is no backward compatibility. Most v4 call sites change shape;
the semantic fixes (native Timestamp storage, honest write verbs) are the
point of the release.

## Removed

| v4 API | v5 replacement |
|---|---|
| `insert()` / `update()` / `upsert()` | `set(model)` (full replace), `create(model)` (returns the generated ID) |
| `modify((u) => ...)` diff engine | `patch((p) => [...])` with explicit ops; transactions for read-modify-write |
| `FirestoreODM.serverTimestamp` / `autoGeneratedId` sentinels | `p.field.serverTimestamp()`; `create()` returns the ID |
| `aggregate(...).stream` / `count().stream` | one-shot `aggregate(...).get()` / `count()` (no fake streaming) |
| `exists()` | `get()` |
| interface mixin files / `services/` layer | direct runtime classes |
| `fast_immutable_collections` fields | plain `List`/`Map`/`Set` |
| `odm.posts(postId)` subcollection accessors | `odm.usersPosts(postId)` (path-derived names) |

## Changed

- **DateTime is a native Timestamp** both directions — never an ISO string.
  The ODM owns storage serialization; your model's `toJson`/`fromJson`
  (freezed/json_serializable) remain for JSON interchange only.
- The schema class is now declared by hand (`class AppSchema extends
  FirestoreSchema`); generated code lands in `<library>.g.dart`.
- Patch update maps use native `FieldPath` components, preserving literal dots
  in field names while retaining nested-path semantics.
- `OrderedQuery` pagination is stable when the orderBy includes the
  `$.documentId` selector (Firestore's recommended tie-breaker).

## New in 5.0

- `create()` returns the generated document ID.
- Typed bulk writes: `patchAll` / `deleteAll` chunked to Firestore's
  500-write batch limit.
- Recorded benchmark harness and a live emulator e2e lane.
- Strict read validation: documents that no longer match the model fail fast.

## Steps

1. Update packages: `firestore_odm`, `firestore_odm_builder` → 5.0.0.
2. Declare your schema class; point `@Schema` at it.
3. Replace write calls per the table above.
4. Replace sentinels with explicit patch ops.
5. Regenerate code (`dart run build_runner build`).
6. Run the unit suite, then the emulator e2e lane.
