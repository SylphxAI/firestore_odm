# ADR 0002 — Semantics Contract v1 (5.0 clean break)

- **Status:** Accepted — binding contract for the 5.0 line.
- **Supersedes:** v3/v4 runtime semantics (ISO-string DateTime storage, sentinels,
  insert/update/upsert triad, `modify()` diff engine, fake aggregate streaming,
  unbounded query batches). No backward compatibility; v4 consumers must migrate.

## Context

v1–v4 drifted from Firestore's actual server contract: DateTime was stored as an
ISO8601 string instead of a Timestamp (mixed types once `serverTimestamp` was
used), `update()` was a full `set()`, batch `update()` was identical to
`insert()`, `modify()` silently rewrote user intent into `FieldValue` operations,
aggregate `.stream` downloaded every document and computed client-side, and bulk
query writes exceeded Firestore's 500-write batch limit. The fake test suite
could not observe any of these defects.

## Decision

The ODM means exactly what `cloud_firestore` means. Every public API maps 1:1
to a Firestore primitive; nothing is emulated client-side; nothing is magic.

### Type mapping (storage)

| Dart | Firestore | Notes |
|---|---|---|
| `DateTime` | `Timestamp` | Native both directions. Server-set times only via `patch` `serverTimestamp()` op. |
| `Duration` | `int` (µs) | Documented convention. |
| `int/double/num/bool/String` | same | — |
| `Map<String,V>` / `List` / `Set` | Map / Array / Array | `Set` serializes to Array; duplicate semantics on write are Firestore's. |
| `GeoPoint` / `Blob` / `DocumentReference` | same | Passthrough. |
| enum | name or `@JsonValue` | Kept from v4. |
| nested model | Map | Kept from v4. |
| `@JsonKey` | subset: `name`, `ignore`, `includeFromJson/ToJson`, `@JsonConverter` | Documented subset; no silent partial support. |

### Write verbs

| ODM | Firestore primitive |
|---|---|
| `Collection.create(T)` → `String` (generated ID) | `collection.add()` |
| `Collection.set(String id, T)` / `Document.set(T)` | `doc.set(data)` (full replace) |
| `Collection.patch(String id, ops)` / `Document.patch(ops)` | `doc.update(map)` |
| `Collection.delete(String id)` / `Document.delete()` | `doc.delete()` |
| `Query.patchAll(ops)` / `Query.deleteAll()` | Chunked batches (≤500 writes each) |
| Transaction/Batch variants | `Transaction` / `WriteBatch` |

Patch ops are exactly the six `FieldValue`-shaped operations: `set`, `delete`,
`increment`, `arrayUnion`, `arrayRemove`, `serverTimestamp`. No map-DSL ops, no
precedence resolution.

### Removed (with reason)

- `modify()` — read-modify-write races + unsound atomic guessing. Transactions +
  explicit patch ops cover the use cases exactly.
- `insert`/`update`/`upsert` — lied about semantics (full `set`, TOCTOU
  existence checks). Replaced by create/set/patch.
- `FirestoreODM.serverTimestamp` / `autoGeneratedId` sentinels — magic values in
  user namespaces; generated IDs now returned by `create()`; server time via
  patch op.
- Aggregate `.stream` and `count().stream` — fake client-side aggregation.
  Aggregates are one-shot (native `AggregateQuery`). Server-side aggregate
  streams will be added only when `cloud_firestore` exposes them.
- `exists()` — trivial `get()`.
- 15 interface mixin files, `services/` layer, 11-op patch DSL — surface without
  value.
- `fast_immutable_collections` coupling — Firestore stores plain collections.
- String `FieldPath` representation chosen for `fake_cloud_firestore` — native
  `FieldPath` is used; the fake supports it.
- `cloud_firestore_platform_interface` dependency — native types only.

### Kept

- Annotations + codegen selector philosophy (`$.field`).
- `FirestoreODM(schema, {firestore})` entrypoint; multiple instances.
- Deferred-write transactions with document caching.
- Object-cursor pagination; **new:** automatic `documentId` tie-breaker.
- One-shot aggregates; typed Pipelines (experimental, Enterprise-gated, ADR-0001).
- Sealed exception taxonomy aligned to `FirestoreException` codes.

### Verification gates

- **Source:** semantics contract tests (type mapping both directions; each write
  verb against emulator), builder golden tests, strict analysis.
- **CI:** unit (fake) + golden + emulator e2e + benchmarks + `dart pub audit`;
  all six doctrine contexts gate.
- **Deploy:** dry-run → publish → pub.dev readback → docs readback; stable-only
  tags; dev versions never published.
- **Live:** emulator e2e in CI; opt-in Enterprise pipeline lane before
  pipeline bulk/update-delete stages leave experimental.
