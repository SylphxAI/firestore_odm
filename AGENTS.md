# firestore_odm

Type-safe Firestore ODM for Flutter and Dart. Three pub.dev packages
(`firestore_odm`, `firestore_odm_annotation`, `firestore_odm_builder`), one
version, released by pushing a `v<version>` tag. [CONTRIBUTING.md](CONTRIBUTING.md)
has the layout, commands and release steps; [PROJECT.md](PROJECT.md) the scope.

- Run `melos bootstrap`, then `melos run check`. Generated `*.g.dart` files are
  not committed, so run `melos run generate` before analyzing or testing.
- Test behaviour through the generated API in `apps/flutter_example/test`; a
  test that reads source text passes while the behaviour is broken.
- Code generated by a new builder must compile against the same-version
  runtime only: builder and runtime ship together.
- The fake Firestore does not model every query (for example filtering by a
  `DocumentReference`); cover those in `integration_test/`, which the merge
  queue runs against the emulator.
- Public text (README, docs site, dartdoc, changelog) uses plain customer
  terms: no decision-record numbers or internal jargon.
